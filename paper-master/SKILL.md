# Paper Master

面向计算神经科学、大脑建模、复杂系统与脑认知领域的研究读者。解释研究问了什么、证据支持什么、方法如何工作，并按用户所选模块评议或扩展文献。语言严谨、简明、易懂；解释新符号和关键推理，不重复铺陈读者已熟悉的基础知识。

## 四个可组合模块

| 编号 | 名称与常见说法 | 交付与按需读取的说明 |
| --- | --- | --- |
| 1 | `summary`／基本总结／精读／模型解析 | [七节通用总结](references/general-summary.md)；聚焦技术、算法或模型时用 [六节技术解析](references/model-analysis.md)。这是同一模块的两个子模式。 |
| 2 | `critical-thinking`／批判性分析／科学审稿 | [评议说明](references/critical-thinking.md)：主张与证据是否匹配、关键问题、影响与可执行的改进。 |
| 3 | `research-lookup`／找相关论文／查证文献 | [检索说明](references/research-lookup.md)：经过核实的相关研究、与目标的关系、支持或冲突及阅读优先级。 |
| 4 | `literature-review`／文献综述／文献覆盖审查 | [综述说明](references/literature-review.md)：按主题综合证据；审初稿时默认检查文献覆盖、引用支撑和创新性表述。 |

- 接受编号组合、英文名、中文名和自然语言，如“1+2+3”“除综述外都用”“四个全开”“只审逻辑和文献覆盖”。明显拼写错误可按语义理解，不要求命令语法。
- 明确选择了哪些模块，就只输出哪些模块；模块可任意单选或组合，不强制包含 1。未指定模块、仅给论文或要求阅读总结时默认 1；明确要求评议、检索或综述时按实际意图选择。用户指定的问题、篇幅和结构优先。
- 开头简短注明本次模块与材料覆盖，直接执行，不为确认选项多问一轮。仅加载被选模块需要的说明；1 的两种模板不默认同时加载。
- 只有 2+4 时，必要的研究定位用几句话交代，不附完整七节总结。2、4 为核实证据可以检索，这不意味着必须选择或额外输出 3。

调用示例：

```text
$paper-master 模块1+2+3，精读这篇论文：题目或DOI
$paper-master 四个模块全用，模块1按技术／模型模式，重点解释方程和证据边界：题目
$paper-master 只用critical-thinking和literature-review，审阅附件中的初稿，给修改建议。
```

## 共享阅读与组合执行

1. 确定输入、版本、所选模块和问题范围。题目／DOI／公共网页按下文取材；用户文件或粘贴的初稿按 [输入材料说明](references/input-materials.md) 读取。不要用同题发表版替代用户指定的稿件。
2. 读取一次目标材料，整理核心主张、证据位置、方法、公式与缺口。所选模块需要外部文献时，共用同一批核实过的来源；检索结果可以供评议与综述使用，执行顺序不必等于输出顺序。
3. 输出仅含所选模块，通常按 1→2→3→4 排列。单模块保留其自然结构；多模块将各自结构放入对应模块下。公共身份、覆盖声明和书目只整理一次。
4. 同一公式、结果或问题只在最合适的位置展开，其他模块简短指回。1+2 时，1 的讨论保留作者观点，深入评议与改进放 2；3+4 时，3 给文献与证据记录，4 综合主题和分歧，不逐条重述表格。

从科学问题、可观测量、假设和证据出发判断。默认做与当前问题相称的有限检索或综述，不设参考文献数量指标，不自动启动多 Agent、付费服务、绘图、仿真或 PDF 生成。正式系统综述需要明确范围与检索筛选记录，不能把一次普通网页检索包装成已完成系统综述。

## 网页取材与身份核实

1. 用准确题目或 DOI 搜索，核对题目、作者、年份、期刊／预印本平台、DOI 或 arXiv ID。题目相近但对象不同且会影响总结时才澄清；仅标点或译名差异可凭身份信息解决。
2. 优先期刊 HTML 全文；同文不可达时，寻找 PMC／Europe PMC、作者或机构的合法全文、arXiv HTML 等。预印本与正式发表版要分别注明，不把不同版本的方程、参数和结论无标识地拼接。用户指定版本时尊重它。
3. 搜索结果片段用于定位，打开并实际读取来源才用于总结。摘要页、博客、新闻及其他模型生成的摘要不能当成论文全文。遇到验证码、付费墙或访问失败，换合法来源；连续尝试同一路径没有新信息时停止重试。
4. 以题目、DOI 或公共链接查文献时，默认网页优先，不下载、解析或 OCR PDF。用户明确要求或已授权使用 PDF 时按授权处理；仅给公共 PDF 链接时先找同文网页。用户提交 PDF 文件让你阅读／审稿，已授权本地读取，不再询问 PDF 许可，详见输入材料说明。
5. 网页全文可用时，读摘要、主要 Results、Methods、Discussion，以及支撑关键主张的图注、表格和在线补充材料。不要因摘要足够流畅就停止。补充材料只按关键需求取读，不默认遍历全部附件。
6. 材料足以回答所选模块的问题后停止重复检索。只做 1 时通常保留主要全文与必要引用；3、4 的检索范围由其说明和当前问题决定。使用当前可用的网页检索、出版方／学术库页面与合法 API，不要求 Parallel、OpenRouter、专用连接器或新安装依赖。

## 阅读覆盖与证据规则

- 报告开头注明论文身份或稿件文件名、采用版本、访问／读取日期，以及实际阅读范围：全文／部分章节／仅摘要。明确未读的补充材料、缺失的公式或图表；初稿分析区分用户材料与外部文献的证据。
- 只有摘要或部分正文时，仍可交付有用的有限总结，但标题／开头必须说明范围；只回答已读材料支持的部分，参数和完整方法写“当前可读材料不足”。如关键问题必须依靠 PDF 且尚未获授权，说明缺口并询问是否允许使用 PDF，不擅自补造细节。
- 将关键结果关联到原文节名、图号、表号或方程号，并附可用的原文链接。不必每句话重复同一个 URL，但关键定量结论和方法必须能定位。
- 区分四种内容：作者的假设、报告的观测／仿真结果、作者的解释、你提出的解释或后续建议。假设不写成结果；相关不写成因果；模型内扰动结果不直接当成真实大脑的因果证据；拟合好不等于机制已证实。
- 保留影响解释的样本量、分析单位、实验条件、比较基线、效应与不确定性。仅在相关时检查训练／测试分离、参数可辨识性、空模型、结构连接与功能连接等，避免对每篇硬套临床研究的偏差评分。批评对应材料中的具体证据或明确缺口。
- 没看到某项信息时写“已读材料未见／未报告”，不要断言作者没有做。网页提取失败与原文缺失要明确区分。

## 公式、参数与算法

- 保留支撑论文机制和结论的核心公式；按原符号逐项解释变量、参数、索引、单位／无量纲性及关键非线性。说明模型输入、状态、输出的结构，以及输出如何对应测量或评价指标。
- 公式必须来自实际读到的原文表达。若网页文字丢失公式，先检查页面的可读 MathML、替代文本、公式图像或同版本 HTML；仅查看相关公式，不启动整篇 PDF 解析。仍看不到时标记“方程未核对”，保留方程号及链接；不要凭领域记忆填成该文的原式。
- 任何重写、简化或补充推导都明确标注为讲解，说明与原式的关系；不得混淆原文报告与推导所得，也不必为每个公式做冗长推导。
- 参数说明区分固定常数、拟合值、扫描范围、初值、数据估计值及情景特定设置。精确值、单位和来源可核实时才填表；常用默认值和引用模型的数值不能自动算作本文使用值。
- 同一论文的正文、图注、参数表或补充材料出现不同设置时，先检查是否对应不同实验；无法解释的冲突并列注明来源，不能自行挑一个数值当作统一设置。
- 对算法，解释目标函数／约束、更新或求解步骤、停止条件及验证指标。原文没有报告的细节直接标缺，不自行实现算法或跑仿真。

## 引用与组织

- 总结模块保留所选模板结构，各节内部尽量沿原文顺序；评议按影响组织，综述按主题组织。用户要求原文章节顺序或其他结构时从其要求，不强制七节模板。
- Result 写具体证据，Conclusion 写证据支持的结论，Method 写如何得到；同一内容只详细讲一次，其他位置简短指回。
- 总结中实际提到其他论文时，在对应主张附近链接到 DOI、期刊页或可信预印本。可从目标论文的参考文献记录定位引文，但要标明“目标论文引用，未另读全文”；若使用该引文独立支撑额外事实，先打开相关一手来源核对。
- 找不到可靠引文链接就保留作者／年份等已知信息并注明“链接未核实”，不编造 DOI，也不将搜索结果页作为已核实文献链接。不为未讨论的参考文献创建完整书目。
- 输出自己的概括，不大段复制论文、图注或既有总结，遵守当前来源的引用与使用限制；需要更多细节时指向原文。

## 可复制 Markdown 交付

- 默认在对话中给可阅读分析，并额外提供内容一致的 UTF-8 `.md` 文件，避免把整篇正文重复输出两遍。组合模块默认合成一个报告。用户指定位置则按该位置交付；否则在当前任务可写目录下选择清楚的新文件名，例如 `outputs/paper-master/年份-短标题.md`，保留已有文件及输入稿件。
- 文件使用标准 Markdown 标题、列表、表格和 `[文献](https://...)` 链接；行内公式写 `\(w_{EE}\)`，独立公式写 `\[ ... \]`。保留真正的反斜杠和 LaTeX 下划线，不写成 `\\(` 或 `w\_{EE}`，不用 HTML 转义串代替字符。表格中公式的竖线用 `\lvert`、`\rvert` 等避免破坏列结构。
- 用户禁止写文件或环境无法写文件时，额外提供原始 Markdown 代码块；正文含代码围栏时使用更长的外层围栏。用户只要一种版本时不额外复制。
- 发文件前读回，核对公式定界符、链接和内容没有因转义而改变。不承诺所有 Markdown 查看器都会渲染数学公式；需要时按用户目标软件调整，未经要求不改其数学写法。

## 交付前检查

确认选项和输出一致，未擅自加模块；读的是指定材料与版本；覆盖声明符合实际读取；核心论点与重要公式有来源；参数未由记忆补齐；缺口与科学解释的限度已说明；各模块不重复且符合用户问题；Markdown 可复制；输入稿件未被擅自修改。若证据不足，清楚交付有限结论，不用更长的文字掩盖缺口。
